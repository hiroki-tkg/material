# Domuz 発表スライド

事業の数字を「1ページ1メッセージ」で見せる資料の型。取引先向けの AP/AF 資料、その社内向け版、ハナイチ資料は
すべてこの型で作られていて、読み手はこの見た目に慣れている。見た目を揃えることで、読み手は「どこを見ればいいか」を考えずに数字に集中できる。

## 進め方

1. **テーマを決める**。話題の事業で配色が決まる。アンドプランツ＝`ap`、アンドフラワー＝`af`、ハナイチ＝`hanaichi`、
   事業横断や社内一般＝`domuz`（AP と同じライトグリーン）。AP と AF を1つの資料で扱うときは、資料全体は `ap` にして
   AF のページだけ `content_slide(..., accent=FLOWER)` と `draw_claims(..., color=FLOWER)` で切り替える
   （AP/AF を並べた取引先向け資料がこの形）。どの事業の話か迷ったら、依頼者に聞くより先に、数字の出所（どの管理画面・どのシート）で判断する。
2. **数字を先に固める**。`data_xxx.py` に月次や期別の数列と定数（税抜・百万円）を置き、出典をコメントで残す。
   本文の数字はすべて f-string でデータから組み立てる。手打ちの数字は、後で数字が変わったときに食い違いの原因になる。
3. **`build_deck.py` を書く**。`scripts/deck_lib.py` を `sys.path` に足して `from deck_lib import *`、
   `use_theme("hanaichi")`（例。事業に合わせる）の後にページを順に追加する。部品の使い方は `scripts/example_deck.py` が全部の見本
   （3つのテーマで動く）。ページの中身の決め方は `references/pages.md`。
4. **要約ページは最後に書く**。`content_slide(タイトル)` で枠だけ先に作っておき、全ページの数字が出てから
   `draw_claims` で埋める（例の `summary = content_slide(...)` → 末尾で `draw_claims(summary, ...)`）。
5. **書き出して目で確認する**。`bash scripts/render.sh out.pptx "タイトル" "2026.10 株式会社DOMUZ"` で
   PDF → ページごとの SVG → 単一 HTML → 確認用 PNG まで作る。PNG を必ず見て、文字の重なり・はみ出し・2行になった見出しを直す。
   `references/pitfalls.md` に、これまで実際に起きた崩れと直し方がある。
6. 納品物は **PDF と HTML の2つ**。HTML は SVG を埋め込んでいるので、相手の環境にフォントがなくても同じ見た目になる。
   pptx は編集用で、Google スライドに取り込むと文字の位置が少しずれる。

## 必要な環境

python-pptx、LibreOffice（`soffice`）、poppler（`pdftocairo`・`pdftoppm`・`pdfinfo`）、
フォント Montserrat と Zen Kaku Gothic New（PDF 化する機械に入っていること。HTML は SVG なので閲覧側には不要）。
Pillow があると確認用の一覧画像が作れる。

## デザインの約束

- **キャンバスは 1128×846 px**（10in 幅）、左右の余白 56px、本文幅 1016px。座標はすべて px で指定する。
- **タイトルは結論**にする（「売上の推移」ではなく「売上は3期で拡大、限界利益率は30%台を維持」）。
  サブタイトルに期間・単位・注記（※税抜、ボックス等は含まない）。
- **色は3種類だけ**。テーマ色（主役の棒・番号・左端の帯）、グレー（比較対象・控除）、赤（マイナス・警告）。
  本文は MOSS（濃い緑）、補足は SECONDARY（灰）。色で意味を増やさない。
- **数字は百万円・税抜**、小数1桁。マイナスは ▲。率は整数%。千円単位のものは「4,672円」のように円で。
- **矢印は半角スペースを挟んで「12 → 34 → 60」**。インライン強調は `[[語]]`（テーマの濃い色・太字）、
  `!!語!!`（赤・太字）、`**語**`（太字）。
- **注記は脚注へ**（`footnote`、※で始めて2行まで）。本文に但し書きを混ぜない。定義は最後の用語ページにまとめる。
- **ページ構成の定型**：表紙 → 本資料の構成 → 要約（事業ごとに1ページ） → 章扉 → 本編 → 用語と集計の前提。
  章扉は全面テーマ色（ハナイチは黄地に MOSS 文字）。章を跨ぐ比較は章扉を挟まず同じ章に置く。
- **グラフは図形で描く**（python-pptx のネイティブグラフは使わない）。Google スライドでも PDF でも同じ見た目になり、
  ラベルの位置を自分で制御できる。

## 部品（scripts/deck_lib.py）

| 部品 | 用途 |
|---|---|
| `use_theme(name)` | 配色の切り替え。`T.accent` `T.light` `T.dark` `T.divider_bg` `T.divider_fg` で参照 |
| `cover(label, [title...], sub, [meta...])` | 表紙 |
| `agenda(title, [(番号, 見出し, 説明)])` | 本資料の構成（3〜4項目） |
| `content_slide(title, sub, accent=None)` | 本編ページの枠（左端の帯＋タイトル＋ページ番号） |
| `message(s, 結論)` | タイトル直下の結論1行（サブの代わり） |
| `divider(num, EN_LABEL, 和文タイトル, sub)` | 章扉 |
| `draw_claims(s, [(番号, 主張, [根拠...])])` | 要約。根拠は全角47字までなら1行 |
| `kpi_table(s, x, y, w, header, rows, col_w, bold_rows)` | 主要指標の表（値は右寄せ、— は灰）。row_h は 32 以上 |
| `bar_chart(s, x, y, w, h, labels, series, vmax, ticks, ...)` | 縦棒（並べる／積み上げ）。戻り値 `ax` の `ax.x(i)`・`ax.yv2(右軸の最大)` で線を重ねる。線を重ねるときは vmax を最大値の1.5倍にして上を空ける |
| `polyline(s, pts, color)` | 折れ線（ROAS、比率など右軸の系列） |
| `waterfall(s, x, name, steps, end_label, end_val, sales)` | 売上=100 の控除ウォーターフォール（1ページに2〜3本） |
| `ranked_bars(s, x, y, w, rows, ref=1.0)` | 基準線つき横棒ランキング（LTV/CAC など） |
| `big_number(s, x, y, label, value, unit)` | 大きな数字（KPIの見せ場） |
| `legend(s, x, y, [(ラベル, 色)], line=False)` | 凡例。グラフのタイトルと同じ高さに置く |
| `terms_page(title, [(用語, 定義)])` | 用語と集計の前提（10行前後まで） |
| `footnote(s, 本文)` / `text` / `rect` / `hline` / `vline` / `badge` | 低レベル部品 |

## 参照

- `references/pages.md`：ページごとの中身の決め方（表紙に何を書くか、要約の3主張の作り方、エコノミクスページの段の切り方、LTV/CAC の定義）
- `references/pitfalls.md`：レンダリングで実際に起きた崩れと直し方（ラベルの重なり、凡例の2行化、黄の線が見えない、など）
- `references/design-tokens.md`：色・フォント・サイズの一覧
